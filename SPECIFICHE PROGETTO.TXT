4. MODELLO DATI - TABELLE BASE
================================================================================
Queste tabelle devono esistere prima delle migrazioni annualità/contabilità.
I tipi UUID sono preferibili per soci e tabelle collegate.

4.1 soci
Profilo tecnico del tesserato. Non sostituisce il libro soci associativo.
Campi richiesti o usati dall'app:
- id uuid PK default gen_random_uuid().
- codice_fiscale text, idealmente unico e normalizzato maiuscolo.
- nome text, cognome text.
- data_nascita date, luogo_nascita text.
- residenza_indirizzo text, residenza_cap text, residenza_citta text,
  residenza_provincia text.
- email text, telefono text.
- corso_scelto text: legacy/compatibilità, non fonte annuale primaria.
- is_minore boolean.
- nome_tutore text, cognome_tutore text, cf_tutore text.
- privacy_accettata boolean, liberatoria_immagini boolean: legacy/snapshot.
- consenso_gdpr boolean, consenso_immagini_video boolean: compatibilità legacy.
- data_iscrizione date, created_at timestamptz, updated_at timestamptz.
- scadenza_certificato_medico date, certificato_medico_url text: legacy;
  la fonte corrente è documenti_medici.
- scadenza_tessera_asi date, data_tesseramento_asi date.
- stato/stato_approvazione text.
- mesi_non_praticante text[]: chiavi "mese-anno", es. "9-2026".
- pagamento_iscrizione_2627 boolean: compatibilità UI corrente.

4.2 corsi
Catalogo corsi.
- id uuid PK.
- nome_corso text unico.
- categoria text: usare "Bambini" per corsi bambini; "Adulti" o NULL per
  adulti/altri. Esempi: Ninjutsu Adulti/Ragazzi, Ninjutsu Bambini,
  Vietvodao Adulti/Ragazzi, Vietvodao Bambini, Shodo (Calligrafia Giapponese).
- quota_mensile numeric.
- istruttore text legacy, orari text.

4.3 iscrizioni_corsi (legacy)
Relazione socio-corso non stagionale, mantenuta per compatibilità e migrazione.
- id uuid/bigint PK.
- socio_id uuid FK -> soci.id.
- nome_corso text.
- stato text, data_iscrizione date/timestamptz.
Vincolo: UNIQUE (socio_id, lower(trim(nome_corso))) tramite indice funzionale.

4.4 pagamenti
Pagamenti annuali e mensili.
Campi usati:
- id PK.
- socio_id uuid FK -> soci.id.
- importo numeric, importo_totale numeric.
- metodo text: contanti | bonifico.
- stato text: Approvato | In attesa di verifica | altri stati legacy.
- corso text; per nuova mensilità salvare il nome effettivo del corso.
- tipo_pagamento text: Iscrizione Annuale | Mensilità | Tranche |
  Lezione Singola.
- periodo_riferimento text, mese_riferimento integer, anno_riferimento integer.
- anno_accademico text nel formato AAAA/AAAA.
- data_pagamento date, data_inserimento timestamptz, ricevuta_url text.
- validato_da_email text, validato_da_nome text, validato_il timestamptz.
Regola: Iscrizione Annuale non entra nel calcolo del compenso istruttore.

4.5 presenze
- id uuid PK default gen_random_uuid().
- socio_id uuid FK -> soci.id.
- data_presenza date.
- corso text NOT NULL.
- created_at timestamptz.
Indice/unique consigliato: UNIQUE (socio_id, data_presenza, corso).
Non salvare mai corso come "undefined" o "null"; record legacy così formati
non sono attribuibili con certezza al corso e non vanno conteggiati.

4.6 istruttori_corsi
Account applicativo e competenze.
- id bigint PK (richiesto dal FK contabile attuale).
- socio_id uuid NULL FK -> soci.id.
- email text unique, nome text, password_accesso text.
- ruolo text: presidente | istruttore.
- corsi_competenze text[] NOT NULL.
- corsi_disabilitati text[] NOT NULL DEFAULT '{}'.
Regola: un istruttore con tutti i corsi disabilitati non accede al pannello.

5. MODELLO DATI - ANNUALITA', DOCUMENTI E CONSENSI
================================================================================
Anno accademico: dal 1 agosto viene proposta la nuova stagione; formato
"2026/2027". I mesi accademici sono Settembre-Agosto.

5.1 iscrizioni_annuali
- id uuid PK default gen_random_uuid().
- socio_id uuid NOT NULL FK -> soci.id.
- nome_corso text NOT NULL.
- anno_accademico text NOT NULL, CHECK regex ^[0-9]{4}/[0-9]{4}$.
- stato text NOT NULL default "In Attesa".
- privacy_accettata boolean, liberatoria_immagini boolean: snapshot annuale.
- scadenza_certificato_medico date, certificato_medico_url text: compatibilità.
- data_invio timestamptz, data_approvazione timestamptz, approvata_da text.
- richiesta_istruttore boolean default false.
- stato_richiesta_istruttore text default "Nessuna", valori: Nessuna, In attesa,
  Confermata, Rifiutata.
- created_at, updated_at timestamptz.
Vincolo: UNIQUE (socio_id, nome_corso, anno_accademico).

5.2 documenti_medici
- id uuid PK.
- socio_id uuid NOT NULL FK -> soci.id.
- anno_accademico text NOT NULL.
- file_url text NOT NULL. Non creare un documento senza file.
- nome_file text, scadenza date.
- caricato_il timestamptz default now(), caricato_da text.
- attivo boolean default true.
- conservare_fino_al date NOT NULL.
- eliminato_il timestamptz NULL.
- created_at timestamptz.
Vincolo: al massimo un documento attivo e non eliminato per socio/stagione:
UNIQUE (socio_id, anno_accademico) WHERE attivo AND eliminato_il IS NULL.
Quando viene caricato un nuovo documento, disattivare quello attivo della stessa
stagione prima dell'insert. La modifica della sola scadenza aggiorna il record
attivo esistente; non creare record senza file_url.

5.3 consensi_tesseramento
- id uuid PK.
- socio_id uuid NOT NULL FK -> soci.id.
- anno_accademico text NOT NULL.
- tipo: presa_visione_privacy | foto_video.
- stato: dato | negato | revocato.
- versione_testo text NOT NULL.
- canale text default modulo_web.
- registrato_il timestamptz default now().
- revoca_di uuid NULL FK -> consensi_tesseramento.id.
Indice: (socio_id, anno_accademico, registrato_il DESC).

5.4 storico_modifiche (opzionale, non sempre migrato)
Se viene usato: id UUID, socio_id FK, iscrizione_annuale_id FK, utente_email,
utente_nome, campo, valore_precedente, valore_nuovo, motivo, modificato_il.
L'API delete-socio deve trattarlo come tabella opzionale perché ambienti già
operativi possono non averlo.

6. MODELLO DATI - CONTABILITA' ISTRUTTORI
================================================================================
6.1 corsi_config_contabile
Una riga per corso.
- id uuid PK.
- nome_corso text UNIQUE NOT NULL.
- categoria text NOT NULL default Adulti.
- soglia_alunni integer NOT NULL.
- perc_istruttore_sotto numeric(5,2), 0..100.
- perc_istruttore_sopra numeric(5,2), 0..100.
- istruttore_principale_id bigint NULL FK -> istruttori_corsi.id ON DELETE SET NULL.
- aggiornato_da text, aggiornato_il timestamptz, created_at timestamptz.
Default inserimento da corsi:
- categoria Bambini: soglia 5, 50% sotto soglia, 60% da soglia in poi.
- tutti gli altri: soglia 7, 50% sotto soglia, 60% da soglia in poi.
- la configurazione è sempre modificabile dal presidente per singolo corso.

6.2 contabilita_mesi
Una riga solo quando un mese viene personalizzato o chiuso.
- id uuid PK.
- nome_corso text, mese integer 1..12, anno integer.
- stato text: OPEN default | LOCKED.
- is_custom_override boolean default false.
- tipo_override: fisso | percentuale.
- valore_override numeric(10,2).
- bloccato_da text, bloccato_il timestamptz, notificato_il timestamptz.
- created_at, updated_at timestamptz.
Vincolo UNIQUE (nome_corso, mese, anno).

Calcolo conguaglio mensile per corso:
- Considerare soltanto pagamenti Approvati di Mensilità; escludere sempre
  Iscrizione Annuale.
- C = somma metodo contanti.
- B = somma metodo bonifico.
- T = C + B.
- Alunni = unione di soci che hanno una presenza valida nel mese/corso OR un
  pagamento mensile Approvato nel mese/corso. Ogni socio conta una sola volta.
- Se non c'è override: percentuale istruttore = perc_sotto se Alunni < soglia,
  altrimenti perc_sopra. Q_istr = T * percentuale / 100.
- Override percentuale: Q_istr = T * valore_override / 100.
- Override fisso: Q_istr = valore_override.
- Q_pal = T - Q_istr.
- Conguaglio = C - Q_istr.
  - positivo: istruttore versa contanti alla palestra;
  - negativo: palestra accredita il credito all'istruttore.
- La tabella mostra alunni, contanti, bonifici, totale, quota istruttore,
  quota palestra, conguaglio, stato e override; include riga totali.

Locking:
- Il presidente può confermare uno o più mesi OPEN: diventano LOCKED e viene
  inviata la notifica al solo istruttore principale.
- Un mese LOCKED non è selezionabile per nuova conferma, quindi non genera una
  seconda email accidentalmente.
- Il presidente può sbloccare un singolo mese tramite popup di conferma;
  sbloccare non invia email. Una nuova email parte solo alla successiva conferma.
- L'istruttore non può modificare/aggiungere incassi su mese LOCKED; il
  presidente mantiene l'accesso.
- Le presenze retroattive restano salvabili: non modificano righe LOCKED.

8. FRONTEND: FLUSSI OBBLIGATORI
================================================================================
8.1 Iscrizione (iscrizione.html)
- Acquisisce dati tesserato, corso, tutore se minore, consensi e certificato.

  salvare in PostgreSQL.

8.2 Area tesserato (socio.html)
- Accesso con codice fiscale.
- Visualizza anagrafica, stato annualità, quota, certificato e consensi.
- Permette pagamento e upload/sostituzione certificato.
- Non permette attualmente modifica autonoma dell'anagrafica.
- Mantiene temporaneamente la lista dei profili trovati in localStorage con
  chiave foundTesseratiList; la sessione admin usa invece asd_admin_user.

8.3 Registro amministrativo (admin.html)
- Mostra soci, annualità, quota, certificato, ASI, privacy, foto.
- Colore certificato: rosso se mancante/scaduto, giallo entro 30 giorni,
  grigio oltre 30 giorni.
- Il presidente modifica scadenza certificato sul record documenti_medici
  esistente e scadenza ASI su soci.
- Colonna Azioni solo presidente:
  - Matita: modifica nome, cognome, CF, email, telefono, indirizzo, CAP, città.
  - Cestino: richiede testo ELIMINA e password amministratore.
  - L'eliminazione è consentita solo senza pagamenti, presenze e annualità
    approvata; altrimenti correggere con matita/archiviare.

8.4 Presenze (presenze.html)
- Il presidente vede tutti i corsi; istruttore solo i propri corsi attivi.
- Salva righe socio_id, data_presenza ISO, corso esatto.
- Prima rimuove le presenze di quel corso/data per gli iscritti e poi inserisce
  l'elenco aggiornato, evitando duplicati.
- Calcola percentuale presenza su lezioni uniche del corso.

8.5 Scadenze (admin-scadenze.html)
- Carica soci e documento medico attivo corrente.
- Mostra scadenze critiche: assenti, scadute o entro 30 giorni.
- Istruttore vede solo i propri corsi; presidente vede tutto.
- Pulsante invio manuale chiama POST /api/scadenze-alert.

8.6 Contabilità (admin-contabilita.html)
- Griglia mensile pagamenti, filtro anno solare/accademico e corso.
- Gestione pagamento rapido: contanti/bonifico, approvazione, morosità/non
  praticante. Istruttore non modifica mesi LOCKED.
- Presidente configura soglia, percentuali e istruttore principale.
- Conguaglio visibile solo con un corso specifico, non "Tutti i corsi".
- Pagamenti legacy con corso = "Mensilità" devono essere attribuiti al corso
  del socio tramite pagamentoAppartieneAlCorso, non esclusi per confronto diretto.

9. API VERCEL: CONTRATTI
================================================================================
GET /api/index
Risposta stato con associazione, codice fiscale e affiliazione.

POST /api/send-email
Body: tipo opzionale (approvazione), nome, cognome, email, telefono,
codice_fiscale, corso.
- tipo=approvazione: email al tesserato + cc admin.
- altro: conferma al tesserato + cc admin, poi notifica admin separata.
- from EMAIL_FROM, reply_to admin, cc admin.

GET|POST /api/scadenze-alert[?socio_id=<uuid>]
- GET: invia solo alle soglie automatiche medico 45/30/15 e ASI 15.
- POST: invio manuale medico/ASI entro 30 giorni.
- socio_id è un filtro di test applicato dopo la lettura della vista; non usare
  un filtro PostgREST su socio_id perché la vista può esporre id.
- Cron Vercel: GET ogni giorno alle 08:00 UTC, path /api/scadenze-alert.

GET|POST /api/check-expirations[?socio_id=<uuid>]
Endpoint compatibile alternativo; stesso mittente/reply-to e stesse soglie GET.

POST /api/notifica-conguaglio
Body: corso, istruttoreEmail, istruttoreNome, righe[], totaleCumulativo.
Ogni riga: meseLabel, anno, contanti, bonifici, totale, quotaIstruttore,
quotaPalestra, conguaglio.
Invia al solo istruttore principale con cc/reply-to admin; oggetto:
[Fight Academy] Notifica Conguaglio - Corso <corso> - Mesi: <elenco>.
Corpo HTML con tabella e totale cumulativo.

POST /api/regolamento-pagamenti
Body: socioId, email, codiceFiscale.
Verifica il socio via service role e restituisce URL firmato del regolamento,
valido 600 secondi.

POST /api/delete-socio
Body: socioId, adminEmail, password, confirmation="ELIMINA".
- Verifica che l'account in istruttori_corsi sia ruolo presidente e password valida.
- Blocca se esistono pagamenti, presenze o iscrizioni_annuali Approvato.
- Elimina consensi_tesseramento, documenti_medici, iscrizioni_annuali,
  iscrizioni_corsi e, se presente, storico_modifiche; poi soci.
- storico_modifiche deve essere opzionale: ignorare PGRST205 se tabella assente.

12. POLICY, RETENTION E LIMITI LEGALI OPERATIVI
================================================================================
- La tabella soci è un profilo tecnico di tesseramento sportivo, non il libro
  soci previsto dalla vita associativa/statuto.
- Per dati di tesserati con pagamenti, presenze, contratti o conguagli, non
  effettuare cancellazione fisica senza valutare obblighi contabili, fiscali,
  contrattuali e privacy con il consulente competente.
- L'eliminazione definitiva in app è destinata a prove, duplicati e domande
  abbandonate senza attività.
- Per istruttori cessati: disabilitare corsi e preservare lo storico. Non
  eliminare account che hanno svolto attività o ricevuto compensi/conguagli.
- La gestione dei contratti Co.Co.Co., chiusure/aperture contrattuali e relativi
  adempimenti resta esterna all'app.

13. CONVENZIONI TECNICHE
================================================================================
- Date database/API: ISO AAAA-MM-GG.
- Date mostrate e richieste da UI: GG-MM-AAAA, convertite esplicitamente in JS.
- Mesi: integer 1-12; anno: anno solare del mese.
- Anno accademico: AAAA/AAAA, Settembre-Agosto.
- Corso: usare esattamente il nome del catalogo; normalizzare solo per confronti
  di compatibilità. Non salvare valori "undefined", "null" o "Mensilità" come
  corso per nuovi pagamenti/presenze.
- ASCII preferito nei file di codice; nomi visualizzati possono contenere lettere
  accentate italiane.
